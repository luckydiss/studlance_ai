# 07. Кабинет клиента (`web/client`)

Визуальная основа — [DESIGN.md](../DESIGN.md) и макеты [design/mockups/](../design/mockups/). Экран `/` делать **точно по** `Main.dc.html` (те же тексты, размеры, цвета, отступы, анимации). Остальные экраны — по описанию ниже и в том же стиле.

## Общее

- **Токены** (CSS-переменные в `web/shared/src/theme.css`): стол `#ECEDF0`, фон страницы `#FFFFFF`, текст `#15171A`, вторичный `#4A4E55`, приглушённый `#686C73`, рамки `#E4E5E8` / `#D9DBE0`, действие `#1F3A93` (hover `#162C70`), выделение-замечание `#1F3A93` с заливкой `rgba(31,58,147,0.12)`, успех `#2B8A3E`. Шрифт интерфейса — Golos Text (400/500/600/700), листы — PT Serif / PT Sans (только в макетах-заглушках). Радиусы: поля и карточки 16, кнопки 10, чипы 8.
- **Шапка** (56 px, белая, нижняя граница `#E4E5E8`): слева «studlance» (18/700) и ссылка «Мои заказы» → `/orders`; справа кружок с инициалами (32 px) — по клику меню «Выйти».
- **Данные и сессия:** приватные данные (заказы, страницы) и SSE-подписки относятся к текущему пользователю: ключи кеша включают идентификатор пользователя (`['job', <user_id>, <id>]`, `['jobs', <user_id>]`). 401 от клиентского API завершает локальную сессию: `me` → `null`, приватные запросы отменяются, их кеш и подписки SSE с таймерами закрываются до показа формы входа; устаревший кеш `me` не может вытолкнуть пользователя с формы. При входе (в т. ч. смене аккаунта) кеш очищается до показа новой сессии; запоздалые HTTP-ответы, mutation-callbacks и события SSE прежней сессии не могут вернуть её приватные данные в новую. Обычная сетевая ошибка — не 401: страница остаётся с кнопкой «Повторить». При 404 «Заказ не найден» имеет приоритет над любыми прежними данными заказа.
- **Экземпляр сессии (поколение):** клиент считает поколение сессии; оно инкрементируется при завершении сессии (401 → локальное завершение, `me` → null), выходе и начале нового входа — включая повторный вход того же пользователя. Запрос, мутация и подписка захватывают поколение **при запуске**; колбэк (успех, ошибка, progress) с устаревшим поколением игнорируется до любых побочных эффектов: записи/инвалидации кеша, навигации, завершения сессии, toast и изменения текущих форм. Центральный обработчик 401 знает поколение инициатора и не завершает новую сессию по старой ошибке; локальные обработчики ошибок подчиняются тем же правилам. Колбэки актуальной сессии работают как обычно.
- **Данные:** TanStack Query; страница заказа подписана на SSE `/api/client/jobs/{id}/stream`. Поток присылает **полный `JobDetail`**: сначала `event: snapshot` (состояние на момент подключения), далее `event: job` при каждом изменении; `: ping` — служебный комментарий, его игнорируем. Оба события заменяют данные заказа в кеше. При обрыве SSE — переподключение с паузой 1→2→5→10 с: новый `snapshot` восстанавливает актуальное состояние. При уходе со страницы подписка и её таймеры очищаются.
- **Ошибки API:** показывать `error.message` в тосте внизу по центру (4 с); 401 → на `/login` с возвратом на текущую страницу после входа.
- **Доступность:** настоящие `<button>`, `<a>`, `<input>` + `<label>`; фокус виден; иконки — inline SVG с `aria-label`; контраст текста ≥ 4.5:1.
- **Адаптивность:** до 760 px колонки складываются в одну, стопка листов на `/` масштабируется (`transform: scale` по ширине контейнера), карусель — вертикально: текст над картинкой.
- **Тексты** — ровно как в спеке. Слова «ИИ» допустимо только там, где оно есть в макете («ИИ сделал работу», «ИИ доработает»). Никаких «агентов», «codex», «claude», «проверки нейросетью», «трейса».

## `/login`

Белая страница, по центру карточка 360 px: «Вход в studlance» (24/600), поля «Почта» и «Пароль», кнопка «Войти» (на всю ширину, `#1F3A93`). Ошибка под кнопкой красным `#C92A2A`: текст из `error.message`. После входа — на `?next=` или `/`. Регистрации и «забыли пароль» нет.

## `/` — новый заказ (макет `Main.dc.html`)

Три секции, как в макете:

1. **«Что нужно сделать?»** — заголовок, подзаголовок, форма:
   - поле запроса (textarea, авто-высота от 2 до 10 строк, placeholder «Например: курсовая работа, вариант 14, всё по методичке кафедры»);
   - чипы прикреплённых файлов (имя; папка — «имя папки · N файлов»; кнопка × на каждом, `aria-label="Убрать"`);
   - нормализация путей не переименовывает сегменты: допустимые пробелы в именах файлов и папок сохраняются как есть (разделители `/`/`\` нормализуются, пустые сегменты, `.` и `..` отбрасываются); замена загруженного файла допустима только при точном совпадении пути;
   - «Прикрепить файлы или папку» — меню из двух пунктов: «Файлы» (`<input type=file multiple>`), «Папку» (`webkitdirectory`); плюс перетаскивание файлов и папок на всю форму (подсветка рамкой `#1F3A93`; папки обходить через `webkitGetAsEntry`, сохраняя относительные пути);
   - «Оформить заказ» — активна, если запрос ≥ 20 символов или есть файл. Заказ с одними файлами и пустым запросом допустим: черновик создаётся с пустым `prompt` (см. [04](04-api.md)); submit без файла и без запроса ≥ 20 символов сервер запрещает.
   - Отправка: `POST /jobs` → последовательная загрузка файлов `PUT /jobs/{id}/input?path=…` (до 3 параллельно) с общим прогрессом на кнопке («Загружаем… 45 %») → `POST /submit` → переход на `/orders/{id}`. Ошибка загрузки файла — повтор до 3 раз, затем тост «Не удалось загрузить <имя>. Попробуйте ещё раз» и кнопка «Повторить»; заказ остаётся в статусе «Загрузка файлов» и его можно дозагрузить со страницы заказа (повтор работает с тем же `job_id`, новое создание заказа не выполняется; после перезагрузки браузера уже загруженные файлы берутся из API, недоступные локальные файлы пользователь выбирает снова).
   - Лимит: суммарно больше лимита сервера — тост «Слишком много файлов: максимум 2 ГБ на заказ».
2. **«Любые работы — готовым комплектом»** — текст и стопка трёх листов (`/demo/stack-*.jpg`), как в макете.
3. **«Как это работает»** — карусель-сторис из 5 этапов, 20 с по кругу, полоски прогресса, тексты и картинки (`/demo/how-*.jpg`) как в макете. Пауза при наведении мыши и при фокусе внутри; клик по полоске — перейти к этапу (тогда анимация управляется из React: таймер 4 с на этап, CSS-переход `transform 0.6s cubic-bezier(0.7,0,0.3,1)`). `prefers-reduced-motion` — без автопрокрутки, этапы листаются кликом по полоскам.

## `/orders` — мои заказы

Заголовок «Мои заказы» (28/600) и кнопка «Новый заказ» справа. Список строками (не карточками): название (16/500, обрезка в одну строку), под ним дата создания «4 октября, 14:20» и «версия 2» (если есть); справа текст статуса цветом: «Готово» — `#2B8A3E`, «Нужно уточнение» — `#B35C00`, «Задерживается…» — `#686C73`, остальные — `#1F3A93`. Клик — на заказ. Пусто: «Заказов пока нет» и кнопка «Новый заказ».

## `/orders/:id` — заказ

**Шапка заказа:** назад «← Мои заказы», название (24/600), под ним текст статуса и дата. Справа: «Скачать всё» (если есть версия; `GET …/versions/{v}/bundle.zip`), «Отменить заказ» (если `can_cancel`; подтверждение «Отменить заказ? Работа будет остановлена.» — «Отменить» / «Не отменять»).

**Основная область — «стол»** (`#ECEDF0`, на всю ширину под шапкой). Состояния:

| Состояние | Что на столе |
|---|---|
| `uploading` | список файлов заказа, зона дозагрузки как на `/`, кнопка «Отправить заказ» (`submit`) |
| `accepted`, `in_progress` без версий | заготовки листов: белые листы A4 (пропорция 1:1.414) с названием и типом документа из `planned_documents` («Пояснительная записка · Word»); если их ещё нет — три пустых листа с подписью «Готовим комплект» и мягкой пульсацией (opacity 0.6–1, 1.6 с) |
| `needs_input` | над столом карточка вопроса (белая, рамка `#B35C00` слева 3 px): «Нужно уточнение», текст вопроса, textarea «Ваш ответ», кнопка «Ответить» |
| есть версия (`done`, `revising` и др.) | **просмотр комплекта** (ниже) |
| `delayed` | заготовки + плашка «Задерживается — мы уже разбираемся. Обычно это занимает до часа.» |
| `canceled` | «Заказ отменён» и ссылка «Новый заказ» |

**Просмотр комплекта** — три колонки (на узком экране — одна):
- слева (240 px): переключатель версий («Версия 2 · сейчас», «Версия 1»), под ним документы версии: мини-копия первой страницы, название, тип и «32 стр.», ссылка «Скачать» (файл документа);
- в центре: страница документа крупно (ширина до 760 px, белый лист с тенью как в макете), под ней «‹ стр. 16 из 32 ›» и стрелки клавиатуры ←/→; ниже — лента мини-копий страниц документа (горизонтальная прокрутка);
- справа (320 px): панель доработки (ниже).

Если смотрят не последнюю версию — над листом строка «Это версия 1. Последняя — версия 2» со ссылкой. Если для документа нет превью (`page_count = 0`) — вместо листа карточка «Этот файл нельзя показать на сайте» и «Скачать».

**Доработка** (доступна при `can_revise`, т. е. `done`, на последней версии):
- кнопка «Нужна доработка» включает режим замечаний: курсор-крестик над листом; протянуть мышью (или пальцем) прямоугольник → рамка `#1F3A93` 1.5 px с заливкой `rgba(31,58,147,0.12)` и номером в углу; рядом поповер «Что поправить?» (textarea, «Добавить», «Отмена»);
- замечания списком в правой панели: номер, «стр. 16, Пояснительная записка», текст, «Удалить»; клик — переход к месту;
- под списком: поле «Общий комментарий» и «Приложить файлы»;
- «Отправить на доработку» (активна при комментарии или ≥1 замечании) → `POST /revisions` → статус «Дорабатываем», режим выключается, замечания остаются видны на этой версии (рамки без заливки, номер).
- Координаты рамки — доли от размеров картинки страницы (0–1), с точностью 4 знака.

**Окошко статуса** — фиксировано внизу справа (отступ 24 px), ширина 320 px, белое, радиус 14, тень как у карточек. **Пока `client_status = uploading`, окошко скрыто целиком**: сервер в этом состоянии отдаёт шаг «Заказ принят», но отправки заказа ещё не было. Свёрнутое: одна строка — точка статуса и текст статуса, стрелка «развернуть». Развёрнутое: шаги из `status_steps` (готово — зелёная галочка, текущий — синяя точка с пульсацией, будущий — серый кружок), если есть вопрос — его текст и кнопка «Ответить» (прокрутка к карточке вопроса). Автоматически разворачивается при смене статуса, сворачивается кликом; состояние запоминается в `localStorage` на заказ. На `done` без доработки — показывает «Готово — версия N» и через 10 с сворачивается.

## Тесты (Playwright, на фейковых агентах)

Harness — `web/e2e` (пакет `@studlance/e2e`, `pnpm -C web/e2e run e2e`): сам собирает фронт и Go-бинарники, поднимает отдельный сервер, воркера и `cmd/fakeagent` с временной БД и файлами, создаёт тестовых клиентов и завершает свои процессы. Сравнение с макетом: comparator обязан явно сравнивать исходные ширину и высоту — нулевой цветовой diff при разных размерах не считается равенством; self-check включает одинаковые, различные по цвету, различные по ширине/высоте изображения, включая белые. Фаза полосок прогресса карусели синхронизируется фиксацией анимации в момент снимка (пауза/остановка только в render-wrapper снимка); продуктовая анимация ради сравнения не меняется. `pnpm -C web/e2e run lighthouse` — аудит доступности, `pnpm -C web/e2e run visual` — скриншоты для сравнения с макетом.

Вход и выход; новый заказ с файлами и папкой → статус «Заказ принят» → окошко статуса проходит шаги → «Готово — версия 1» → листание страниц → скачивание файла и архива; вопрос (`#ask`) → ответ → готово; доработка с двумя замечаниями-рамками → «Дорабатываем» → «Версия 2», переключение версий; отмена; чужой заказ по прямой ссылке → «Заказ не найден». Плюс: заказ только с файлами и только текстом; неудачная загрузка с повтором на том же заказе; обрыв SSE с переподключением; 390 px без горизонтального переполнения; reduced-motion; demo-картинки отсутствуют — белые листы.
