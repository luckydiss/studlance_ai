# 00. Что строим

## Продукт

Сайт, где студент загружает материалы работы (задание, методичку, вариант, примеры — любые файлы и папки) и пишет запрос своими словами. Дальше без участия людей:

1. **codex** (CLI) делает полный черновой комплект: записка в Word, расчёты в Excel, чертежи в КОМПАС-3D, код со скриншотами запуска, презентация — что требует задание.
2. **claude** (CLI) проверяет всё по заданию и методичке и **сам исправляет**, доводя до финала.
3. Готовый комплект (версия 1) появляется у студента в кабинете: просмотр листов, скачивание файлов и архива.
4. Студент может выделить место на листе и написать замечание → claude дорабатывает в той же сессии → версия 2, 3…
5. Если агенту не хватает данных, он задаёт студенту вопрос; заказ ждёт ответа.

Проверка нейросетью — внутренняя кухня: студенту о ней не говорим. Студент видит только свою работу и простые статусы.

## Роли

| Роль | Кто | Что может |
|---|---|---|
| `client` | студент | свои заказы: создать, загрузить файлы, ответить на вопрос, отменить, смотреть и скачивать версии, отправить на доработку |
| `admin` | владелец сервиса | всё по всем заказам: трейс агентов, черновик и финал, ответ за клиента, повтор, отмена, заметки |
| воркер | программа на ПК | забирать закреплённые заказы, отдавать трейс, файлы, итог |

Пользователи создаются командой сервера (регистрации нет). На старте: один `admin` и один тестовый `client`.

## Границы MVP

- Всё работает **на одном ПК с Windows**: `studlance-server.exe` и `studlance-worker.exe`, без Docker, без отдельной СУБД. База — SQLite-файл, файлы — папка на диске.
- Сайт открывается по `http://localhost:8080` на этом ПК (доступ извне — не в MVP).
- Один воркер, один заказ за раз.
- Агенты работают по подпискам владельца (вход в codex и claude выполнен в учётной записи Windows, под которой запущен воркер).
- Код хранилищ — за интерфейсами (`store.Store`, `blobs.Blobs`), чтобы позже заменить на Postgres и S3 без переписывания логики.

## Не входит в MVP

Регистрация и восстановление пароля, оплата, уведомления (email/Telegram), несколько воркеров одновременно, автоскейлинг, Postgres/S3/Docker, мобильная вёрстка пульта (кабинет — адаптивный), юридические вопросы хранения данных.

## Словарь

| Термин | Значение |
|---|---|
| заказ (job) | одна работа студента со всеми версиями |
| комплект | набор файлов результата одной версии (`out/`) |
| версия | v1 — первый результат, v2… — после доработок |
| этап (stage) | `draft` (codex), `verify` (claude), `revise` (claude) |
| доработка (revision) | запрос студента на изменения: комментарий + замечания на листах + файлы |
| замечание (remark) | выделенная область на странице документа + текст |
| трейс | шаги агентов (сообщения, команды, файлы), видит только админ |
| lease | аренда заказа воркером на 60 с, продлевается heartbeat'ом |
| epoch | счётчик выдач заказа (fencing): запись со старым epoch отклоняется |
