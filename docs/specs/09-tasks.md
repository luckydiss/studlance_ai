# 09. Порядок работ и приёмка

Каждый пункт — отдельный PR в ветку `main` (или ветку, указанную владельцем). Следующий PR начинается после того, как предыдущий принят. Ревьюер проверяет по критериям ниже; «как проверить руками» — в описании PR.

## PR 1. Каркас

- Структура репозитория, `go.mod`, `Makefile`, `scripts/build.ps1`, `.golangci.yml`, CI ([01](01-repo-build.md)).
- `internal/config`, `internal/store` (интерфейс + SQLite + миграция `00001_init.sql` из [02](02-data.md)), `internal/blobs` (интерфейс + fs).
- `studlance-server`: `serve` (только `/healthz` и отдача заглушки фронта), `migrate`, `user create`, `worker token`, `backup`.
- `web/` — pnpm workspace, пустые приложения `client` и `admin` с роутером, `shared` с темой; сборка в `internal/web/dist` и отдача сервером (`/`, `/admin`, SPA-фолбэк), `/demo/*`.

**Принять, если:** CI зелёный; на Windows `scripts/build.ps1` собирает оба exe; `studlance-server serve` создаёт `data/studlance.db`, `/healthz` → 200, `/` и `/admin` отдают собранные приложения; `user create` создаёт пользователя с Argon2id-хэшем; тесты store (CRUD пользователей, миграции на пустой базе), blobs (атомарная запись, запрет `..`).

## PR 2. Контракт API, вход, заказы клиента, live

- `api/openapi.yaml` целиком по [04](04-api.md) (все пространства, включая воркера), генерация Go и TS, проверка в CI.
- `internal/auth`: вход, выход, `me`, сессии, cookie, проверка `Origin`, лимит попыток, middleware ролей.
- `internal/jobs` + обработчики `/api/client/*` и чтение `/api/admin/*` (без трейса воркера): создание, загрузка файлов, submit, список, карточка (`client_status`, `status_steps` по [03](03-lifecycle.md)), ответ, отмена, доработка (multipart), файлы/страницы/архив версии, события.
- `internal/live` и SSE для клиента и админа.

**Принять, если:** юнит- и HTTP-тесты: вход/выход/неверный пароль/429; клиент не видит чужой заказ (404 на всех эндпоинтах); все запрещённые переходы → 409; загрузка с путями папок и запрет `..`; `bundle.zip` с русскими именами открывается в Проводнике Windows; SSE присылает `snapshot` и `job` при изменении.

## PR 3. Очередь и API воркера

- `internal/queue`: выдача (`BEGIN IMMEDIATE`, закрепление за воркером, приоритет: заказы этого воркера в `running` — как `continue`, затем его `queued`, затем ничьи `queued` по `created_at`), lease, heartbeat с флагом отмены, fencing на каждой записи, авто-повтор, таймаут этапа, фоновая отметка `needs_attention` (раз в минуту).
- Обработчики `/api/worker/*` по [04](04-api.md#воркер--apiworker), включая снимки, `commit`, вопрос, `finish`; формирование `Assignment` (`start | continue | answer | revise`).

**Принять, если:** тесты на имитации воркера (HTTP-клиент в тесте): полный путь заказа до `done`; вопрос → ответ → `action: answer`; доработка → `action: revise`, версия 2; сбой → авто-повтор (`attempt = 1`) → второй сбой → `failed` + `needs_attention`; истёкший lease → повторная выдача тому же воркеру с `action: continue` и новым epoch; запись со старым epoch → 409 `stale_lease`; повтор пачки шагов не дублирует; отмена во время `running` → флаг в heartbeat → `canceled`; два параллельных `claim` не получают один заказ.

- `studlance-worker serve` и `probe` по [05](05-worker.md): цикл, рабочая папка, `TASK.md`, `REVISION-N.md`, вырезки, этапы и действия, запуск агентов через stdin, разбор JSONL codex и claude, трейс пачками, сырые логи, снимки, конвертация в PDF, `pdftoppm`, мини-копии, сравнение страниц, Job Objects и закрытие Office/КОМПАСа на Windows, Ctrl+C.
- Промпты [06](06-prompts.md) в `prompts/`.
- `cmd/fakeagent` со сценариями.

**Принять, если:** юнит-тесты парсеров на настоящих записанных логах codex и claude (положить в `testdata/`, 3–5 разных); e2e на Linux: сервер + воркер + фейковые агенты проходят сценарии обычный / `#ask` / `#fail-once` / `#fail-verify` / `#hang` + отмена / `#no-pdf` / доработка с замечаниями (вырезки на месте, `REVISION-2.md` по формату) / убить воркер посреди этапа и перезапустить → `continue`; на Windows (руками, инструкция в PR): `probe` показывает codex, claude, kompas, word, excel; отмена во время работы закрывает дерево процессов агента и запущенный им Excel.

## PR 5. Кабинет

По [07](07-web-client.md): `/login`, `/` (точно по макету `Main.dc.html`), `/orders`, `/orders/:id` со всеми состояниями, окошком статуса, вопросом, просмотром комплекта, версиями, скачиванием, доработкой с выделением областей.

**Принять, если:** Playwright-сценарии из [07](07-web-client.md#тесты-playwright-на-фейковых-агентах) зелёные; `/` визуально совпадает с макетом на 1440 px (скриншот в PR рядом со скриншотом макета) и не ломается на 390 px; Lighthouse Accessibility ≥ 90 на `/` и `/orders/:id`. Обязательные регрессии: смена пользователя/истечение сессии не показывают чужой кеш (404 «Заказ не найден» приоритетнее прежних данных, запоздалые SSE/ответы прежней сессии игнорируются); 401 при свежем `me` открывает форму входа с корректным `next` и возвратом после входа (сетевая ошибка — не 401); имена файлов с пробелами сохраняются байт-в-байт (два имени, отличающиеся пробелами, — два разных файла, замена только по точному пути), при этом проверяются точные байты на сервере (скачивание через API воркера после пути через UI), а не только размеры; запоздалый 200 старой сессии после повторного входа того же пользователя не появляется ни в одном DOM-обновлении (MutationObserver до фактической доставки ответа), запоздалый 401 старой сессии после входа другого пользователя не открывает форму входа, не меняет маршрут и не удаляет его сессию; 401 текущей сессии от ручного `PUT /input` (оформление на `/` и дозагрузка на `/orders/:id`) завершает локальную сессию до навигации: форма входа остаётся, `next` указывает на созданный заказ (единый сохранённый источник адреса возврата; auth gate не заменяет его исходной `/` при любом порядке уведомлений Query/эффектов React), тест подтверждает единственный POST, созданный id и **конечный** `next` после обработки переходов, повторный вход открывает тот же заказ без второго POST создания; регрессии ожидают фактического начала и доставки каждого задержанного ответа, а не фиксированной паузы; визуальный comparator самопроверен (одинаковые → 0, разные по цвету → ≠0, разные размеры — включая белые изображения — сообщают несовпадение при нулевом цветовом diff) и сравнивает полные буферы без обрезки; полоски прогресса карусели синхронизированы фикса­цией анимации на снимке. Touch-выделение на масштабированном листе, клавиатура и полный цикл карусели 5×4 с паузой hover/focus подтверждены.
