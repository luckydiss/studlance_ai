# Спецификации MVP

Это задание для агентов-разработчиков. Код пишут агенты по этим документам, владелец проекта и ревьюер проверяют результат по критериям приёмки. Если в спеке чего-то нет или она противоречит себе — **не додумывать**, а остановиться и записать вопрос в описание PR.

Контекст: [ARCHITECTURE.md](../ARCHITECTURE.md) (целевая архитектура), [DESIGN.md](../DESIGN.md) и [design/](../design/) (дизайн и макеты). Где спека и архитектура расходятся, для MVP права **спека**.

| # | Документ | О чём |
|---|---|---|
| 00 | [scope.md](00-scope.md) | что строим, роли, границы MVP, словарь |
| 01 | [repo-build.md](01-repo-build.md) | структура репозитория, инструменты, сборка, конфиги, запуск на ПК |
| 02 | [data.md](02-data.md) | схема SQLite, хранение файлов |
| 03 | [lifecycle.md](03-lifecycle.md) | статусы заказа, переходы, события, что видит клиент |
| 04 | [api.md](04-api.md) | все эндпоинты: запросы, ответы, ошибки, SSE |
| 05 | [worker.md](05-worker.md) | воркер: протокол с сервером, папка заказа, запуск codex и claude, разбор логов, превью |
| 06 | [prompts.md](06-prompts.md) | тексты промптов агентам |
| 07 | [web-client.md](07-web-client.md) | кабинет клиента: экраны, состояния, тексты |
| 08 | [web-admin.md](08-web-admin.md) | пульт админа |
| 09 | [tasks.md](09-tasks.md) | порядок работ (PR за PR) и критерии приёмки |

Правила для всех PR:
- код и идентификаторы — на английском, тексты интерфейса — на русском, ровно как в спеке;
- всё, что можно проверить автоматически, покрыто тестами (`go test ./...`, `pnpm test`) и проходит в CI;
- в описании PR: что сделано, по какому пункту спеки, как проверить руками, что не сделано и почему.
