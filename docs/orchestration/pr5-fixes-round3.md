## P2: текущий 401 PUT /input должен завершать локальную сессию

Подтверждённый сценарий главной:

1. `/me` уже дал пользователя A, кеш свежий.
2. Через UI выбрать файл и оформить заказ. POST `/jobs` создаёт заказ.
3. PUT `/jobs/{id}/input` возвращает 401.
4. `OrderForm` делает только navigate на `/login?next=/orders/{id}`. Локальная сессия и cached `me` остаются.
5. `LoginPage` немедленно делает `<Navigate to="/">`: форма входа не появляется, открывается новая пустая форма главной, теряется возврат на созданный заказ.

Воспроизведение ревью: один POST создания, один PUT с 401; маршруты `/` → `/login?next=%2Forders%2Forder-upload-401` → `/`; login heading ни разу не появился.

В дозагрузке `Uploading` тот же ручной transport вообще не передаёт статус: `runUploads` превращает ApiError в `{path,name,message}`, затем `onError(new Error(message))` не может распознать 401. Обычные QueryCache/MutationCache hooks этот PUT не обрабатывают.

**Сначала уточни 07/09, затем исправляй код.** Уточнения архитектора пока локальные; все правила продублированы здесь:

- Правило 401 относится к ручному PUT при оформлении на `/` и дозагрузке на `/orders/:id`.
- 401 **текущего экземпляра сессии** завершает локальную сессию до навигации и обычных сообщений о повторе: `me=null`, отмена/очистка приватных запросов, закрытие подписок. Используй согласованный существующий механизм завершения сессии; свежий `me` не скрывает форму входа.
- `next` — `/orders/{id}` уже созданного заказа. После входа открывается этот же заказ для дозагрузки; повтор не создаёт второй заказ. Не придумывай восстановление локальных File после перезагрузки: существующая спецификация предусматривает повторный выбор недоступных локальных файлов.
- HTTP-статус нельзя потерять при переводе upload error в outcome. Выбери минимальное согласованное решение для обоих callers, без переписывания всех загрузок и без серверных изменений.
- Контекст сессии захватывай при начале потока. Запоздалый PUT 401 старой сессии после нового входа игнорируется до expire/navigate/toast/изменения формы. Несколько параллельных PUT не должны повторно завершать новую сессию.
- Сетевая ошибка и 413 сохраняют обычную обработку загрузок. Сохранить до 3 параллельных файлов, потоковую передачу File, повторы временных ошибок, точные пути и замену только совпавшего пути.
