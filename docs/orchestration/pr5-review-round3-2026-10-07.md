## P2 — ручная загрузка не завершает локальную сессию по текущему 401

Причина одна для двух UI-потоков: PUT загрузки выполняется вне QueryCache/MutationCache, а его ошибка не доходит до согласованного завершения сессии.

**Оформление на главной.** `web/client/src/pages/home/OrderForm.tsx:158–162` при PUT 401 делает только navigate; `web/client/src/pages/LoginPage.tsx:27` при свежем cached user немедленно возвращает на `/`.

Воспроизведение на точном head через обычный UI и явно замоканные auth/job HTTP fixtures:

1. `/me` 200 для A, кеш свежий; выбрать synthetic файл и заполнить запрос.
2. Нажать «Оформить заказ»: POST `/jobs` создаёт `order-upload-401`.
3. PUT `/input` получает **фактически доставленный 401**.
4. Маршруты `/` → `/login?next=%2Forders%2Forder-upload-401` → `/`.
5. Login heading не появляется ни разу; итоговая главная содержит **пустой запрос и 0 выбранных файлов**, возврат на уже созданный заказ утрачен.

Один POST создания и один PUT; `actualPutStatus=401`, `loginHeadingAdds=0`, `promptValue=""`, `selectedFileCount=0`. Assertions и exit 0: `probe-orderform-upload401-next.mjs/.log/.exitcode`.

**Дозагрузка в карточке.** `web/client/src/uploadQueue.ts:112–121` теряет status при превращении ошибки в `{path,name,message}`; `web/client/src/job/Uploading.tsx:83–86` передаёт `new Error(message)`. `useJobError` распознаёт 401 по status, которого уже нет.

Адресный UI probe: свежий `/me` 200, существующий заказ `uploading-401` в состоянии загрузки, выбрать файл; PUT получил и закончил доставку **401**. Клиент остался на `/orders/uploading-401` с пользователем A, неудачным файлом, кнопкой «Повторить» и тостом «Требуется вход», **без формы входа**. `putDelivered=true`, `loginAdds=0`, assertions и exit 0: `probe-uploading-current401.mjs/.log/.exitcode`.

Оба сценария используют mocked `/me` 200 и PUT 401, чтобы воспроизвести клиентскую гарантию при свежем `me` независимо от серверной гонки. Это не утверждение о реальном изменении серверной сессии. Штатные сценарии отдельно выполнены на настоящем Go server/worker/fakeagent.

**Решение архитектора:** текущий PUT 401 в обеих формах завершает локальную сессию до навигации/обычной обработки повтора; login остаётся с next созданного заказа. Статус нельзя терять на границе upload outcome. Запоздалый PUT 401 старой сессии сохраняет новое поколение и маршрут; ошибки сети/413 остаются обычными ошибками загрузок. Нужны отдельные постоянные регрессии оформления, дозагрузки и старого PUT после входа B. Сервер/воркер и UI-дизайн менять не требуется.

## Пределы и непринятые кандидаты

Постоянные тесты запоздалых answer 200/401 после release ждут только 1500 мс, без явного ожидания начала запроса и доставки ответа. Независимые probes подтвердили текущую реализацию; в следующей адресной сдаче добавить эти ожидания в постоянные регрессии. Это ограничение доказательства теста, не второй продуктовый блокер.

Кандидат навигации OrderForm после задержанной invalidation не воспроизведён: на главной jobs-list query не активна, поэтому нужный delayed refetch не начинался. Отсутствующий `runInSession` у pages query также не принят как баг: доставленный старый pages 401 после входа B не повлиял на B; отмена Query при очистке сессии сработала. Искусственная доставка EventSource после close не использовалась как находка.

Формулировка о bump в начале login и при `/me` 401 не полностью соответствует коду: `/me` 401 возвращает null, login bump выполняется в onSuccess до публикации нового пользователя. Два прежних дефекта после нового входа закрыты, но эти probes не доказывают весь контракт timing; заметка не принята как отдельный P2 без подтверждённого эффекта. Общие гарантии спецификации остаются в силе.

Локальные Go-прогоны без race из-за отсутствия gcc/CGO; race подтверждён CI. Один auth-reviewer не смог запустить свой Go harness из-за PATH (`spawn go ENOENT`); полный реальный прогон другого reviewer прошёл. Неудачные первые probes (неправильный assertion/selector/render path) сохранены и не считаются проверками продукта. Только synthetic данные, без боевых материалов, приватных demo и Office/КОМПАС. Свои процессы завершены, tracked код review worktrees не менялся; merge/push и внешние комментарии не выполнялись.
