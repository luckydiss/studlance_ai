## 1. Автозапуск не должен завершаться через 72 часа

`docs/INSTALL.md:188–189` описывает задания для постоянного сервера и воркера, но не отключает стандартный лимит выполнения. [Microsoft Learn](https://learn.microsoft.com/en-us/windows/win32/taskschd/tasksettings-executiontimelimit) указывает default 72 часа и `PT0S` для бесконечной длительности. Независимая проверка незарегистрированного определения задания на Windows также вернула `PT72H`. Запуск, ожидание 72 часов или регистрация настоящих заданий для этого доказательства не требовались.

**Как исправить:** для обоих заданий явно указать снятие UI-флажка «Останавливать задачу, выполняемую дольше…» и проверку, что `ExecutionTimeLimit` не ограничивает постоянные процессы (`PT0S`). Сохранить интерактивный вход `studlance`, запрет параллельных экземпляров и порядок сервер → воркер. Перезапуск при сбое не подменяет отсутствие лимита. Кратко объяснить условия питания: стандартные `DisallowStartIfOnBatteries`/`StopIfGoingOnBatteries` тоже могут блокировать/останавливать процесс; указать, какие условия владелец выбирает для своего режима постоянной работы. Не менять задачи или питание ПК автоматически.

**Проверка:** инструкция должна позволять владельцу сверить обе задачи в UI либо прочитать Settings существующих задач безопасной командой. Для developer-доказательства допустимо только незарегистрированное определение/объект настроек с нужным execution limit; не добавляй зеркальный тест наличия строки в Markdown. Боевая проверка настройки остаётся действием владельца.

## 2. Сделать получение Poppler для Windows воспроизводимым

`docs/INSTALL.md:34` предлагает владельцу выбрать проверенную Windows-сборку, но не называет источник/комплект или рецепт сборки. [Официальная страница Poppler](https://poppler.freedesktop.org/) публикует исходные релизы; это не готовый Windows-комплект `pdftoppm.exe` с DLL. На чистом ПК владелец сейчас вынужден отдельно исследовать получение обязательной зависимости превью.

**Как исправить:** выбрать и проверить один конкретный способ получения готового portable Windows-комплекта. Указать источник и точную версию/asset, честно обозначить стороннюю сборку, если она не официальная; описать проверку SHA-256/подписи с источником ожидаемого значения, распаковку всей нужной структуры и DLL, точное расположение `pdftoppm.exe` и соответствующий TOML-путь. Не называть сторонний релиз официальным. Не придумывать пакет или ожидаемый хэш. Если готовая сборка не подходит, допустим реально проверенный Windows-рецепт сборки из исходников с зависимостями, командами и результатом. Нельзя оставить выбор поставщика владельцу без рабочего пути.

**Проверка:** получить именно указанный комплект в изолированной временной папке вне Documents и без системной установки. Проверить происхождение/хэш, `pdftoppm -v`, затем конвертировать маленький выдуманный PDF в непустой декодируемый PNG. Проверить запуск по абсолютному пути из другого cwd, желательно с пробелами в пути; результат не должен зависеть от уже установленного Poppler/DLL в PATH. Сохранить raw-доказательства вне репозитория, в отчёт только безопасные команды/версии/итоги. Настоящие работы/приватные demo не использовать.
