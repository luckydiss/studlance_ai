Обнови docs/specs/05-worker.md и 06-prompts.md в своей ветке согласованно с этими правилами.

1. **Не терять вложения после преобразования имён Windows.** Сейчас a:b.txt и a_b.txt оба сохраняются как a_b.txt, первый тихо перезаписывается. Сделай устойчивое отображение серверного пути в уникальный локальный путь, сохраняемое между continue/retry. Учти сравнение без регистра, конечные пробелы/точки, reserved names и сегменты папок. Одно отображение применяется при скачивании, в TASK.md, Files промпта и REVISION-N.md. Сейчас доработка с a:b.txt ссылается на исходное имя, хотя скачан a_b.txt. Тесты: два разных файла с правильными SHA остаются разными; коллизии регистра и папок; после перезапуска имена не меняются; каждый путь Markdown существует и содержит свои байты.

2. **Реальный предел памяти трейса.** Ограничение только stepQueue не помогает: оба парсера навсегда хранят steps, а tailBytes возвращает подстроку, удерживающую весь исходный вывод. 100 событий с 900 КиБ aggregated_output дают около 90 МиБ удержанного heap даже при пустой очереди и отправке каждой пачки. Освобождай отправленные и отброшенные события в парсере, копируй короткие хвосты, учитывай отправляемую пачку и очередь вместе в общем лимите 50 МиБ. Сеть не должна блокировать чтение; лишнее остаётся в сыром логе. Тесты: длительный поток больших событий с исправной сетью и с недоступной сетью 30 с; после восстановления принятые шаги доходят, память не растёт со всем историческим трейсом, сырой лог полный.

3. **Job закрывается при обычном выходе родителя независимо от EOF stdout/stderr.** Сейчас cmd.Wait вызывается только после stdoutDone/stderrDone, а group.Close — после Wait. Родитель может выйти с 0, оставив ребёнка с унаследованными pipes, и Run зависнет до таймаута. Отслеживай выход процесса отдельно от завершения чтения; закрывай Job после выхода родителя, дочитывай остаток лога. Не вводи гонку cmd.Wait с чтением StdoutPipe; выбери корректное владение pipes. После принудительного kill ожидание ≤30 с, затем закрытие pipes и явная ошибка. Закрывай дескрипторы и на ошибках запуска/назначения. Windows-тест: родитель порождает ребёнка, ребёнок держит stdout/stderr и живёт долго, родитель выходит — Run быстро возвращает успех, ребёнок мёртв, лог не обрезан.

4. **Отмена во время снимка.** На живом сервере: задержать PUT snapshot/v1/files, отменить заказ, дождаться heartbeat cancel:true, отпустить PUT — воркер всё равно делает POST snapshot/v1/commit (204). Финальный статус canceled, но недопустимый commit уже прошёл. Прекращай подготовку/загрузки при известной отмене, проверяй флаг непосредственно перед commit и finish ok, включая повтор сетевого запроса. Служебный finish canceled должен иметь рабочий контекст. При stale_lease — остановка без finish. Тесты для draft и v1/vN: после подтверждённой отмены нет commit/finish ok, есть canceled; проверить также ошибку конвертации/загрузки после cancel.

5. **Полный промпт для revise без сессии.** buildPrompt передаёт Retry, но revise.md его не использует и не содержит общего блока. Для каждого этапа draft/verify/revise запуск без сессии получает общий блок, запрос клиента, локальные имена файлов и инструкции этапа. Continue/answer без сессии и start attempt=1 получают блок «Предыдущая попытка не завершилась. В папке могут остаться её частичные результаты — используй полезное, остальное переделай.». Answer без сессии также заканчивается «Студент ответил на вопрос: <ответ>». Обычный revise с известной сессией оставь коротким. Обнови PromptsVersion и specs/06. Табличный тест на все этапы, действия и наличие/отсутствие сессии; существующего draft-only TestBuildPrompt недостаточно.
