# План разработки MVP

Цель MVP — **проверить, что идея работает**: codex делает черновик комплекта, claude проверяет и доводит до финала, доработка по замечаниям даёт новую версию, и всё это запускается из сайта. Всё на одном ПК, **без Docker** и без отдельных серверов БД.

Архитектура для прода — в [ARCHITECTURE.md](ARCHITECTURE.md). MVP — её урезанная версия: тот же протокол «воркер сам забирает заказ по HTTP», те же папка заказа, промпты и статусы, но хранилища простые (SQLite и папка на диске) за интерфейсами, которые в проде заменяются на Postgres и S3. Дизайн — в [DESIGN.md](DESIGN.md).

## Что в MVP иначе, чем в проде

| | MVP | Прод |
|---|---|---|
| Запуск | два exe на ПК: `studlance-server.exe` и `studlance-worker.exe` | сервер в контейнерах, воркеры на VM |
| База | SQLite, один файл (`modernc.org/sqlite`, без CGO) | PostgreSQL |
| Файлы | папка на диске, отдача через сервер | S3, presigned URL |
| Live-статусы | SSE из памяти сервера | SSE + `LISTEN/NOTIFY` |
| Сайт | сервер сам отдаёт собранные фронты | Caddy / CDN |
| Очередь | та же логика claim/lease/heartbeat, в SQLite | в Postgres, `SKIP LOCKED` |

Код хранилищ — за интерфейсами (`Store`, `Blobs`), поэтому переход в прод — это новые реализации и конфиг, а не переписывание.

## Этап 1. Проверка идеи без сайта

Самый короткий путь к ответу «работает ли»: прогнать настоящие агенты на настоящих заданиях.

- `studlance-worker run <папка заказа>` — запускает весь конвейер локально, без сервера:
  1. готовит рабочую папку по [контракту](ARCHITECTURE.md#рабочая-папка) (`input/`, `TASK.md`);
  2. codex, этап `draft` → черновик в `out/`, `manifest.json`, PDF в `preview/`;
  3. снимок черновика;
  4. claude, этап `verify` → финал, `VERIFICATION.md`, `verification.json`;
  5. если появился `QUESTIONS.md` — печатает вопрос, ждёт ответ в консоли, продолжает той же сессией.
- `studlance-worker revise <папка> "замечания"` — claude, этап `revise`, в той же сессии → версия 2.
- Шаблоны промптов в `prompts/`.
- Запуск codex и claude: промпт через stdin, `resume` сессий, сырые JSONL-логи сохраняются, из них — краткий трейс (что делал агент, какие команды, какие файлы), токены и время.
- Windows: дерево процессов агента в Job Object, таймаут этапа, закрытие КОМПАСа и Office после этапа.
- Фейковые codex и claude для автотестов (пишут JSONL и файлы, умеют задать вопрос, упасть, зависнуть).
- `prepare-fixture` — превращает тестовый заказ из приватного репозитория (`fixtures/<имя>/input`, `TASK.md`) в папку заказа.

**Готово, когда:** на вашем ПК 3 заказа из `fixtures/` разных типов (записка + Excel, чертежи в КОМПАСе, программа со скриншотами) проходят черновик → проверку → финал, одна доработка даёт версию 2, а результат сравним с эталоном из `reference/`. По итогам — короткий отчёт: что получилось, сколько времени и токенов, что мешает качеству.

## Этап 2. Сайт поверх конвейера

- `studlance-server.exe`: API, SQLite (миграции встроены), файлы в папке, отдача фронтов.
- Пользователи: админ и тестовый клиент через `studlance-server user create`; вход по email и паролю, сессии в БД.
- Воркер в режиме `serve`: регистрируется, забирает заказы по HTTP (claim, lease, heartbeat, отмена), выполняет тот же конвейер, что на этапе 1, отправляет трейс, файлы и итог.
- Кабинет клиента по утверждённому макету: вход, мои заказы, новый заказ (запрос + файлы и папки), страница заказа со статусом, вопросом и ответом, скачивание комплекта, «Отправить на доработку» с комментарием.
- Пульт админа в минимальном виде: список заказов и трейс заказа.
- Автотесты на фейковых агентах: заказ до «Готово», вопрос → ответ, доработка → версия 2, отмена, сбой → повтор, перезапуск воркера, клиент не видит чужой заказ.

**Готово, когда:** тестовый клиент проходит весь цикл в браузере на ПК, включая вопрос и доработку, на настоящих агентах.

## Этап 3. Работа на листах

- Превью листов: PDF из `preview/` → картинки страниц (`pdftoppm` рядом с воркером); если агент не положил PDF — конвертация docx/xlsx.
- В кабинете: комплект на столе, просмотр страниц, переключатель версий, замечания прямо на листе (метка + текст) → доработка с вырезками мест.
- В пульте: черновик и финал рядом, подсветка изменённых мест.

**Готово, когда:** клиент ставит замечание на лист, получает версию 2 и видит, что поправлено.

## Как ведём работу

- Каждый этап — отдельный PR с инструкцией «как проверить на ПК».
- Код и тесты на фейковых агентах я гоняю в облаке; настоящие codex, claude, КОМПАС и Office проверяются на вашем ПК.
- Решения по умолчанию: Go 1.24 (сборка `.exe` под Windows), фронты на React + Vite + TypeScript, собираются в статику и вшиваются в сервер.
